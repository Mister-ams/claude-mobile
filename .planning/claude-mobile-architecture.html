Why the double crossing exists

It is the price of a deliberate trade. dtach is a Linux tool and Windows has no equivalent detachable session layer, so persistence must live in WSL. Claude Code is authenticated on Windows and the repos sit on the Windows drive, so the agent must run there or pay a 5-20x 9P filesystem penalty. Interop is what reconciles the two.

The cost is real but small: it lands inside the 21-38ms of added echo latency, not anywhere you would feel while typing.

2. Rendering — the genuinely unusual part

Most browser terminals stream raw ANSI to xterm.js and let the client emulate. This one emulates on the server and ships row diffs, so the client never parses an escape sequence.

PTY output -> @xterm/headless mirror exact screen + 5,000 rows of scrollback, server-side -> diff vs last emitted state 0.16-0.25 ms per frame -> CellRun[] run-length encoded {text, sgr} per run, not per cell -> WebSocket 'frame' (changed rows) or 'snapshot' (everything) -> gridTerms{} virtual DOM mounts visible rows + 10 overscan; spacers hold the height
MessageCarriesSent whenCost
frame Changed rows only, coalesced per animation frame Continuously while Claude writes 434 B / keystroke
snapshot Full viewport plus scrollback Connect, tab return, session switch 2.5 MB, 67 ms

Coalescing keeps the frame path cheap: output batches on a 16ms idle timer (COALESCE_IDLE_MS), flushes early at 4KB, and is forced at 64ms. Frames landing in the same paint window merge latest-wins per row before touching the DOM.

Scroll anchoring, new in 3.4.0

A snapshot used to run scrollTop = scrollHeight unconditionally, discarding your reading position on every tab return — measured at +7,230px. It now anchors on the server row ID at the top of the viewport, because indices shift when scrollback rolls but IDs do not, and only follows output when already within GRID_STICK_PX (8px) of the bottom.

The legacy path

A complete xterm.js client still ships behind ?renderer=xterm. It has had zero connections since 4 May and costs 490 KB of uncacheable JavaScript on every page load. Retained deliberately as a fallback, but dead weight today.

3. Security — four layers, not all earning their keep

LayerMechanismHonest verdict
Network Tailscale tailnet, WireGuard, zero public surface; Node binds localhost Load-bearing the real boundary
Identity TOTP plus WebAuthn passkey, 5-attempt lockout, inactivity lock Load-bearing second factor if a device is lost
Session IP-bound tokens, 10 connections per IP Decorative the tailnet already fixes identity to a device
Transport ECDH P-256, HKDF, AES-256-GCM, TOFU pinning, per-direction IV byte Net negative duplicates WireGuard and TLS, and once leaked the TOTP

The security stack is a fossil of a dead threat model

All four layers were built when this was exposed to the public internet through ngrok — the audit log carries real public IPs until 19 March. It has been tailnet-only ever since. That is why the stack looks disproportionate for a single-user tool: it defends a perimeter that no longer exists.

The encryption layer is the clearest case. Both sides derived the same key and built the IV from a counter with no direction bit, so server and client reused a nonce — and because the server's first message is known plaintext, XOR recovered the client's TOTP. Fixed with IV_DIR_SERVER = 1 / IV_DIR_CLIENT = 0, but the layer still sits inside WireGuard and TLS.

CSP is script-src 'self' and connect-src 'self'. style-src still needs 'unsafe-inline' because the grid renderer sets per-cell inline styles. OSC-8 terminal hyperlinks are scheme-allowlisted through the URL API, which also strips embedded tab and newline characters a regex would miss.

4. Persistence — what survives what

EventSessions surviveMechanism
Browser closes, iPad sleepsYes Nothing client-side holds state
PM2 restart, deploy, crashYes dtach daemon outlives Node; recoverDtachSessions() reattaches by socket
Host rebootNo Scheduled task restarts the server, but the dtach daemons are gone
wsl --shutdownUnverified Socket FILES survive on ext4 while daemons do not, so liveness is tested with lsof, never test -S

Session names persist in .session-meta.json. Output history is a 400 KB server-side ring buffer per session. The audit log records 236 server restarts in five months, which is what justifies the dtach layer existing at all.

A trap worth knowing

#app visibility is a class (#app.shown), never an inline style. An inline display outranks every stylesheet rule, so while app.js set it directly the landscape grid could never apply — and it failed silently, looking exactly like a CSS mistake.

8. The shape in one paragraph

A thin, dependency-light Node process owning three hard things: a server-side terminal emulator so the client can stay dumb, a detached session layer in a different operating system so work survives restarts, and an authentication stack built for a perimeter that no longer exists. Two of those three are the right calls. The third is a fossil — and the roughly 520 lines spent compensating for dtach having no API is the honest price of persisting sessions on Windows.
